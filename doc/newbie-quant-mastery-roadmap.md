# Newbie Quant + Coding Mastery Roadmap (This Repo, End-to-End)

This guide turns the repository into a practical training curriculum.

---

## 1) What this project is (in one sentence)

You are building a **multi-asset long/short mean-reversion system** with:
- daily signal generation,
- weekly regime filtering,
- 4H staged execution,
- strict data-quality + risk gates,
- report-first validation workflow.

The current default strategy is **v6** with an analysis overlay layer on top of v5-style core signals.

---

## 2) Architecture map (how data flows)

1. **Data ingest + processing** (`data_pipeline.py`)
   - Pulls Polygon data and builds aligned OHLC matrices.
   - Writes processed `pkl` data used by the backtest.
2. **Quality checks** (`data_quality.py`)
   - Verifies coverage/completeness/breadth before backtest is allowed.
3. **Regime context** (`regime.py`)
   - Builds weekly market state (`RISK_ON`, `NEUTRAL`, `RISK_OFF`).
4. **Core signal + portfolio construction** (`strategy_core.py`)
   - Mean-reversion-style score stack + covariance-aware weighting + hard constraints.
5. **Turnover controls** (`turnover.py`)
   - No-trade band, partial rebalance, turnover caps.
6. **Execution simulation** (`execution_queue.py`)
   - 4H staged fills and execution quality gating.
7. **Analysis overlays (v6)**
   - News + macro + report reconstruction (`news_pipeline.py`, `macro_calendar.py`, `analysis_report_builder.py`, `analysis_scoring.py`, `idea_engine.py`).
8. **Backtest engine** (`backtest_vectorized.py`)
   - Integrates all layers and runs scenarios.
9. **Scenario reporting** (`backtest_report.py`, `ablation_runner.py`)
   - Generates base + stress outputs, acceptance checks, and summary files.

## 3) Repo skills you must master

### A) Quant strategy skills
- Cross-sectional score intuition (who is rich/cheap relative to peers).
- Risk normalization (vol-scaling, gross/net controls, category caps).
- Regime adaptation (different risk posture in `RISK_OFF` vs `RISK_ON`).
- Friction realism (transaction costs, delay, liquidity haircut, borrow costs).
- Robustness thinking (stress tests + ablations, not just single backtest line).

### B) Engineering skills
- pandas time-index handling (daily + 4H alignment).
- Reproducible pipelines (`data/raw` → `data/processed` → `data/reports`).
- Config-driven experimentation via `long_short_config.py`.
- Diagnostics-first workflow (quality reports, overlay tables, acceptance checks).

### C) Research discipline
- Form hypothesis → change 1 knob → rerun scenarios → compare summary JSON/MD.
- Never trust headline Sharpe alone; inspect drawdown, stress behavior, turnover.

## 4) Learn the strategy in layers (recommended order)

### Layer 1: Data and quality gates
Run:
```bash
python data_pipeline.py --build-only
```
Then inspect:
- `data/processed/data_quality_report_v5.json`

Goal: understand why backtests should fail fast when data quality is insufficient.

### Layer 2: Baseline backtest mechanics
Run:
```bash
python backtest_vectorized.py
```
Trace inside `run_backtest(...)` to see:
- date filtering,
- eligible asset selection from quality report,
- regime + signal stack generation,
- weights → execution → PnL.

### Layer 3: Full report and stress framework
Run:
```bash
python backtest_report.py
```
Inspect generated files:
- `summary.md`
- `summary.json`
- `equity_*`
- `daily_returns_*`, `monthly_returns_*`

Goal: learn to evaluate strategy quality beyond one equity curve.

### Layer 4: v6 analysis overlays
Study:
- `analysis_report_builder.py`
- `analysis_scoring.py`
- `idea_engine.py`

Goal: understand how fundamental/news context modifies raw statistical signal.

### Layer 5: Ablation thinking
Run (via report path):
```bash
python backtest_report.py
```
Then inspect ablation outputs generated by `ablation_runner.py` to answer:
- Which overlay contributes most?
- Does removing a component reduce robustness?

## 5) Key config areas to practice (safest learning knobs)

In `long_short_config.py`, practice with these groups:

1. **Risk posture**
   - `REGIME_GROSS_CAP_BY_STATE`
   - `REGIME_SIDE_TILT_BY_STATE`
2. **Turnover/friction realism**
   - `DAILY_TURNOVER_CAP`, `NO_TRADE_BAND`, partial rebalance params
3. **Execution quality policy**
   - `EXEC_QUALITY_*`, `EXEC_MAX_DEFERS`, `NET_EDGE_COST_MULTIPLE`
4. **Stress assumptions**
   - `STRESS_MISSING_DATA_RATIO`, `STRESS_LIQUIDITY_HAIRCUT`, borrow bps
5. **v6 overlay behavior**
   - `V6_OVERLAY_WEIGHTS`, conflict and crisis controls, idea score weights

Rule: modify one cluster at a time and preserve a changelog note for every run.

## 6) 4-week mastery plan

### Week 1 — Foundations
- Read README and this roadmap.
- Run data build + baseline report.
- Write your own summary of each output artifact.

### Week 2 — Signals and risk
- Deep-read `strategy_core.py`, `regime.py`, `turnover.py`.
- Reproduce one result and explain every risk cap in plain English.

### Week 3 — v6 overlays and ideas
- Deep-read analysis modules and map each overlay to expected market behavior.
- Validate whether high-reliability overlays align with realized outcomes.

### Week 4 — Independent research loop
- Propose a small hypothesis (example: tighter turnover cap improves stress stability).
- Implement config change, rerun full matrix, compare acceptance checks.
- Write a mini-research memo (claim, evidence, caveats, next step).

---

## 7) Coding habits that will make you good quickly

- Keep functions pure where possible (input → output, minimal side effects).
- Add diagnostics before optimization.
- Version your experiments with timestamped report folders.
- Avoid changing many knobs at once.
- Treat failed acceptance checks as learning, not failure.

## 8) “Mastery checklist” (you should be able to answer these)

1. Why can a strategy with good return still be rejected?
2. How do regime caps and drawdown controls interact?
3. What is the purpose of execution quality gating at 4H?
4. Why run missing-data and liquidity stress scenarios?
5. How does v6 overlay confidence influence final position sizing?
6. Which outputs would you show an investor vs an engineer?

If you can answer these with code-level evidence, you are already operating like a junior quant researcher.
